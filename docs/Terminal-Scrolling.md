# 터미널 프로그램의 스크롤

검증일: 2026-10-01. Codex CLI 0.159.2와 일반 Lilim 빌드 기준.

## 원인과 수정

Codex는 실행 시 대체 화면(`1049`)과 마우스 추적(`1000`·`1002`·`1003`), SGR 좌표 형식(`1006`)을 요청한다. 기존 Lilim은 마우스 모드를 무시하고 휠 입력을 NSScrollView의 로컬 스크롤로만 처리했다. 대체 화면에는 일반 셸의 스크롤백이 없으므로 Codex에 입력이 전달되지 않았다.

수정 후에는 프로그램이 마우스 입력을 요청한 경우 휠·트랙패드 입력을 PTY로 보낸다. 프로그램이 요청하지 않으면 기존 로컬 스크롤을 사용한다. Shift를 누른 스크롤은 사용 가능한 로컬 기록 탐색으로 처리한다. 전체 화면 프로그램의 기록은 그 프로그램이 관리하며 일반 셸의 출력 기록과 합치지 않는다.

- SGR 좌표와 기존 xterm 바이트 좌표를 구분한다. 휠은 누름 이벤트만 전달한다.
- 좌표는 현재 화면의 셀 기준으로 계산한다. 기존 바이트 형식의 표현 범위를 벗어나면 잘못된 좌표를 보내지 않는다.
- 트랙패드의 작은 이동량을 누적하며 새 제스처·방향 전환·모드 변경 시 남은 이동량을 정리한다.
- 프로그램이 명시적으로 alternate-scroll(`1007`)을 요청하면 대체 화면의 휠을 커서 키로 전달한다. Codex는 이 모드를 끄므로 마우스 이벤트를 사용한다.
- 프로그램 종료와 모드 해제 후에는 일반 셸의 스크롤로 돌아간다.

프로토콜 기준은 [XTerm Control Sequences의 Mouse Tracking](https://invisible-island.net/xterm/ctlseqs/ctlseqs.pdf)이다. 이번 변경은 휠 입력 지원이며 모든 마우스 클릭·드래그·이동 보고를 구현한 것은 아니다.

## 스크롤 표시

일반 셸의 출력 기록에는 항상 보이는 민트색 스크롤바를 사용한다. macOS의 오버레이 스크롤바/자동 숨김 설정과 관계없이 표시하며, 손잡이의 길이와 위치는 실제 로컬 기록의 길이와 현재 화면 범위를 따른다. 손잡이를 드래그하거나 트랙을 클릭해 이동할 수 있다.

Codex처럼 마우스 입력을 요청하는 프로그램은 내부 기록을 관리한다. xterm 마우스 프로토콜은 휠 입력을 전달하지만 전체 기록 길이와 현재 위치를 돌려주지 않는다. Lilim은 이 모드에서 가짜 비율이나 위치를 표시하지 않고, 오른쪽에 항상 보이는 위·아래 버튼을 제공한다. 한 번 누르면 휠 입력 3회, 길게 누르면 반복 전달하며 터미널 입력 포커스를 유지한다. 하단에는 “프로그램 내부 스크롤”을 표시하고 설명을 제공한다. 정확한 내부 위치는 해당 프로그램이 제공하는 표시를 확인해야 한다.

두 모드의 오른쪽 영역 너비는 동일하게 유지해 전환만으로 터미널의 행·열이 바뀌지 않게 한다. 프로그램이 마우스 모드를 해제하면 일반 출력 기록의 위치 막대로 돌아간다.

## 검증

| 검사 | 결과 |
| --- | --- |
| Codex가 실제로 출력한 터미널 모드 | 대체 화면과 `1000/1002/1003/1006` 요청 확인 |
| 같은 PTY 검사 프로그램, 수정 전 | 위로 스크롤해도 수신한 휠 이벤트 0개, 첫 행 080 유지 |
| 같은 프로그램, 수정 후 | 위로 스크롤 시 첫 행 080 → 050, 아래로 스크롤 시 050 → 080 |
| 실제 Codex의 로컬 `!seq 1 120` 출력 | 위로 스크롤 시 98–120에서 1–19로 이동, 아래로 스크롤하면 98–120으로 복귀 |
| Codex 종료 후 일반 셸 | 160줄 출력 후 로컬 스크롤로 최신 130–160에서 이전 1–30행으로 이동 확인 |
| 회귀 검사 | SGR/기존 형식·좌표 범위·모드 분할 입력·커서 모드·대체 화면 종료와 셸 복귀 통과 |
| 일반 출력의 항상 보이는 위치 막대 | 160줄 출력 후 민트색 손잡이 표시, 드래그로 위치 값 1 → 0 및 화면 129–160 → 1–32 이동 확인 |
| 전체 화면 버튼 입력 | 검사 프로그램에서 위 버튼 3회 입력으로 첫 행 080 → 077, 아래 버튼 3회 입력으로 080 복귀 및 터미널 포커스 유지 |
| 실제 Codex의 스크롤 버튼 | 위 버튼으로 이전 기록과 `Back to bottom` 표시 확인, 아래 버튼으로 최신 98–120행 복귀 |
| Codex 종료 후 표시 | 일반 출력 기록의 민트색 위치 막대 및 원래 하단 안내 복귀 확인 |
| 기존 검사 | 파일 작업·탐색·즐겨찾기·한글·크기 변경·PTY·현재 탭 이동 통과 |

실제 사용자 작업과 분리한 검사 앱과 임시 폴더를 사용했다. 검증용 Codex에는 모델 작업을 요청하지 않고 숫자를 출력하는 로컬 셸 명령만 실행했다.

```sh
bash scripts/check.sh
bash scripts/build-app.sh release
```

## 수정 빌드 사용

실행 중인 앱은 교체된 실행 파일을 자동으로 다시 읽지 않는다. 기존 터미널 작업을 마친 뒤 Lilim을 완전히 종료하고 Dock에서 다시 실행한다. 종료 시 앱 소유 셸과 작업이 끝나므로 진행 중인 작업을 먼저 마친다.
